# OBSIDIAN

**برنامهٔ ویندوزی برای ارزیابی امنیت وب‌سایت و API، بررسی شواهد تست نفوذ و تهیهٔ گزارش برای مشتری.**

OBSIDIAN مسیر کار ارزیابی را در یک برنامه جمع می‌کند: URL سایت مجاز را وارد می‌کنی، بخش‌های قابل دسترس برنامه کشف می‌شوند، بررسی‌های قابل اجرا انجام می‌شوند و بعد می‌توانی شواهد هر نتیجه را ببینی و گزارش Word، HTML، Markdown یا JSON بگیری. این ابزار برای پژوهشگران امنیت، تست‌کنندگان نفوذ و توسعه‌دهندگانی است که سایت خودشان یا یک هدف دارای مجوز را بررسی می‌کنند.

موتور داخلی وب با تحلیل JavaScript، کشف API، تأیید مرورگری در صورت فراهم‌بودن پیش‌نیازها و مقایسهٔ حساب‌های آزمایشی ترکیب شده است. برنامه میان «مشاهدهٔ یک تنظیم»، «نامزد آسیب‌پذیری» و «رفتار تأییدشده» تفاوت می‌گذارد؛ صرف وجود یک هشدار یا تعداد زیاد یافته‌ها، اثبات کیفیت اسکن نیست.

## چه بررسی‌هایی انجام می‌دهد

- **نقشهٔ برنامه:** صفحات هم‌مبدأ، فرم‌ها، نام پارامترها، فایل‌های JavaScript و مسیرهای API را همراه با منبع کشف ثبت می‌کند. حروف نام پارامتر و مقدار اولیهٔ قابل استفادهٔ فرم حفظ می‌شوند.
- **JavaScript و source map:** مسیرهای صریح API، نقشه‌های منبع معتبر، مقادیر شبیه اطلاعات حساس و بعضی جریان‌های محلی ورودی به محل مصرف را بررسی می‌کند. مقادیر حساس پوشانده می‌شوند؛ تحلیل ایستا به‌تنهایی اثبات اجرای آسیب‌پذیری نیست.
- **XSS بازتابی:** بازتاب ورودی و بافت HTML را بررسی می‌کند. نامزدهای واجد شرایط می‌توانند با محاسبهٔ بی‌خطر در مرورگر جداگانه تأیید شوند؛ تأیید مرورگری به مشاهدهٔ واقعی نتیجهٔ همان محاسبه نیاز دارد.
- **خطای پایگاه داده:** پاسخ ورودی اولیه، مقدار کنترل و دو درخواست تکراریِ تک‌نقل‌قول را مقایسه می‌کند. خطای جدید و تکرارپذیر به‌عنوان احتمال افشای خطا ثبت می‌شود؛ این نتیجه خودکار به معنی SQL Injection قطعی نیست.
- **ارزیابی قالب:** چند چالش حسابی مستقل و بی‌خطر را مقایسه می‌کند تا نشانهٔ تکرارپذیر ارزیابی سمت سرور را از بازتاب ساده جدا کند. اثر کامل نفوذ یا اجرای فرمان از این محاسبات نتیجه‌گیری نمی‌شود.
- **تنظیمات HTTP:** هدرهای امنیتی، ویژگی کوکی‌ها، سیاست CORS با مبدأهای کنترل‌شده، برخی مسیرهای افشای اطلاعات، تغییرمسیر و نشانه‌های پشتیبانی‌شدهٔ تزریق هدر بررسی می‌شوند.
- **API:** تعریف JSON پشتیبانی‌شدهٔ OpenAPI یا Swagger را کشف یا وارد می‌کند و بررسی محدودِ درخواست‌های GET ناشناس و اعلان‌های احراز هویت را انجام می‌دهد. اختلاف مستندات با پاسخ، به‌تنهایی اثبات دسترسی به دادهٔ خصوصی نیست.
- **انتظارهای کنترل دسترسی:** با حساب‌ها و منابع مصنوعیِ مشخص‌شده، هویت پایه، دسترسی ناشناس و دسترسی غیرمنتظرهٔ تکرارشده با قانون مورد انتظار مقایسه می‌شوند. مالکیت منبع و نقش حساب باید صریحاً تعیین شوند.

بررسی مرز فایل فقط با canary مصنوعیِ از پیش آماده‌شده و نشانگر مورد انتظار در گزینه‌های موتور انجام می‌شود؛ صفحهٔ تنظیم مستقل ندارد و فایل حساس سیستمی خودکار خوانده نمی‌شود.

## از URL تا گزارش

۱. URL پایهٔ هدف دارای مجوز را وارد کن و محدوده را تأیید کن. دکمهٔ اصلی **Scan Website** است؛ تنظیم حساب آزمایشی و OpenAPI در منوی کلیک راست همان دکمه قرار دارد.

۲. موتور داخلی سطح قابل دسترس را کشف می‌کند و ارتباط صفحه، فرم، اسکریپت و مسیرها را ثبت می‌کند. کشف یک زیردامنه به معنی مجوز اسکن آن نیست.

۳. بررسی‌های قابل اجرا با پاسخ پایه، کنترل، سقف درخواست و روش تأیید موجود انجام می‌شوند. نبود ابزار یا پیش‌نیاز به‌عنوان پوشش ناقص، مسدود یا نامشخص ثبت می‌شود.

۴. نتیجه‌ها را فیلتر کن و هر یافته را باز کن تا مسیر، منبع، شدت، اطمینان، وضعیت تأیید، شواهد و راهکار را ببینی. شدت و میزان اطمینان دو مفهوم جدا هستند.

۵. برای همان ارزیابی، Word، HTML، Markdown یا JSON بگیر. گزارش به اسکن انتخاب‌شده و اجرای موتورهای مربوط پیوند دارد و هدف‌های نامرتبط را مخلوط نمی‌کند.

دریافت پاسخ محدود است و تغییرمسیر خودکار دنبال نمی‌شود. دکمهٔ توقف، لغو کار را درخواست می‌کند؛ پاسخ 429 یا 503 جمع‌آوری داخلیِ بعدی را متوقف می‌کند. موتور اختیاریِ در حال اجرا ممکن است ابتدا عملیات محدود خودش را تمام کند.

## گزارش چه اطلاعاتی دارد

گزارش با هدف، زمان، وضعیت اجرا و خلاصهٔ مدیریتی مبتنی بر نتیجه‌های ذخیره‌شده شروع می‌شود. برای یافته‌ها، مؤلفه یا مسیر آسیب‌دیده، ابزار منبع، شدت و مبنای آن، اطمینان، وضعیت تأیید، شواهد پوشانده‌شده و پیشنهاد اصلاح ثبت می‌شود. پیش‌نیاز، مراحل شماره‌دار بازآزمایی و اثر مشاهده‌شده فقط وقتی در شواهد موجود باشند اضافه می‌شوند؛ شاهد و مرحلهٔ انجام‌نشده ساخته نمی‌شود.

پوشش آزمون‌ها نشان می‌دهد چه عملیاتی انجام شده و چه مواردی اجرا نشده، نامشخص، مسدود یا ناموفق مانده‌اند. موارد دقیقاً تکراری تجمیع می‌شوند. اگر یافته‌ای با وضعیت اعتبارسنجی‌شده وجود نداشته باشد، Word این موضوع را صریح می‌گوید. یک گزارش همچنان می‌تواند شامل مشاهده‌های مفید یا نامزدهایی باشد که به بازبینی نیاز دارند.

Word، HTML و Markdown برای مطالعه و تحویل مناسب‌اند؛ JSON رکورد ساخت‌یافتهٔ ارزیابی را نگه می‌دارد. قبل از ارسال، هدف و محرمانگی اطلاعات مشتری و گزارش‌های واردشده را بررسی کن.

## نصب و اجرا

۱. روی **Windows x64** فایل [OBSIDIAN_0.21.0_Windows-x64.zip](https://github.com/III85III/attack-website-tools/releases/download/v0.21.0/OBSIDIAN_0.21.0_Windows-x64.zip) را بگیر.

۲. کل ZIP را در پوشه‌ای قابل نوشتن استخراج کن.

۳. **OBSIDIAN.exe** را اجرا کن و پوشهٔ `_internal` را کنار آن نگه دار. نصب جداگانهٔ Python لازم نیست.

۴. اعلان استفاده را بخوان، هدف مجاز را وارد کن و **Scan Website** را بزن.

۵. شواهد را بررسی کن و با **Export Word report** یا گزینه‌های دیگر گزارش بگیر.

هش فایل را با [SHA256SUMS_0.21.0.txt](https://github.com/III85III/attack-website-tools/releases/download/v0.21.0/SHA256SUMS_0.21.0.txt) مقایسه کن. نسخه امضای دیجیتال ندارد؛ چک‌سام فقط یکپارچگی فایل را بررسی می‌کند. آرشیو خودکار Source code گیت‌هاب، برنامهٔ آمادهٔ اجرا نیست.

## ابزارهای اختیاری و محدودیت‌ها

تأیید مرورگری به Edge یا Chrome معتبر و پشتیبانی‌شده نیاز دارد. اتصال‌های قبلی ZAP از API محلی و Nmap برای بررسی محدود میزبان در صورت دسترسی باقی‌اند. نبود ابزار و وضعیت تأییدنشدن نسخه پنهان نمی‌شود و صرف پیدا شدن یک فایل EXE یا ZIP نشانهٔ آماده‌بودن ابزار نیست.

گزارش‌های پشتیبانی‌شدهٔ Nuclei، SARIF و XML سازگار با Nmap را می‌توان همراه با منبع وارد کرد. واردکردن گزارش، ابزار یا payload آن را اجرا نمی‌کند و نتیجهٔ واردشده خودکار تأیید مستقل نمی‌شود.

نسخهٔ 0.20.0 در تست محلی و CI ویندوز گیت‌هاب **۲۸۹ تست** را گذرانده است. اجرای EXE روی هدف موقت، شمارش درخواست، ذخیرهٔ شواهد و تولید و بازخوانی گزارش را بررسی کرده است. این داده‌ها فقط همان سناریوهای محدود را می‌سنجند و تضمین کشف همهٔ باگ‌ها نیستند.

این نسخه **prerelease و بدون امضای دیجیتال** است. XSS ذخیره‌شده یا blind، چرخهٔ کامل احراز هویت، منطق کسب‌وکار اختصاصی و تحلیل کامل JavaScript پویا همچنان پوشش کامل ندارند یا سناریوی صریح می‌خواهند. صفحه‌آرایی بصری Word هنوز تأیید نشده است. [شواهد تست](../verification/VERIFICATION_0.20.0.json) و [ممیزی فنی](../OBSIDIAN_AUDIT.md) را ببین.

## اجرای کد فعلی

از ریشهٔ مخزن با Python 3.11 در ویندوز:

<div dir="ltr">

```powershell
git clone https://github.com/III85III/attack-website-tools.git
cd attack-website-tools
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r tools/requirements/runtime.txt
.\.venv\Scripts\python.exe -m src
```

راهنمای ساخت و تست در [ساختار مخزن](../REPOSITORY_LAYOUT.md) است. آرشیوهای قدیمیِ نسخه‌ها مسیرهای زمان انتشار خودشان را دارند و تغییر نکرده‌اند.

## حریم خصوصی و پشتیبانی

تاریخچه روی دستگاه ذخیره می‌شود؛ درخواست اسکن از دستگاه تو به هدف می‌رود. کشف غیرفعال گواهی با ارائه‌دهندهٔ آن تماس می‌گیرد و صدای آنلاینِ اختیاری پس از تأیید، متن انتخاب‌شده را برای سرویس صدا می‌فرستد. کلید API، کوکی، نشست و دادهٔ مشتری را در issue عمومی قرار نده. خود برنامه یا پیام تأیید آن، مجوز قانونیِ آزمودن هدف ایجاد نمی‌کند.
